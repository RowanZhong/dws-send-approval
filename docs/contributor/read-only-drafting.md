# 只读起草能力、参数与部署限制

当前 main 配套说明，2026-09-28。本轮代码基线 `6662d54` 已推送 GitHub；两版必要真机验收已完成，包含真实来信、可见卡片、实际按钮及发送结果核对。旧设置、插件 ID、状态路径和 settings version 1 保持兼容；新字段缺失时补默认值，不重置偏好或扩大旧授权。

## 参数与默认值

这些选项在 `plugins.entries.dws-send-approval.config.assistant` 内。参数在插件配置中管理，员工的回复、主题和提醒偏好仍由卡片保存。

| 配置 | 默认值 | 范围与作用 |
| --- | --- | --- |
| `cards.expiryCheckSeconds` | 10 | 5–60 秒；轻量到期检查，发送权限始终按绝对时间校验 |
| `cards.presentationVersion` | 2 | 2 或 3；只有富文本模板发布并验收后才显式设 3 |
| `storage.retentionDays` | 7 | 1–30 天；终态正文保留，不删除发送结果未知及活跃引用 |
| `storage.expiredCardRetentionHours` | 24 | 1–168 小时；到期且已刷失效的卡片保留 |
| `storage.cleanupIntervalSeconds` | 300 | 30–86400 秒；分批清理，与到期检查独立 |
| `storage.dedupeRetentionDays` | 30 | 1–365 天且不短于正文保留；正文删除后保留无正文指纹 |
| `context.historyMinutes` | 5 | 0–60 分钟，0 关闭；私聊双方、群聊发送者与本人 |
| `drafting.toolsEnabled` | false | 新装及升级均默认无工具起草 |
| `drafting.timeoutSeconds` | 120 | 10–600 秒；超时后仍追踪任务，不立即重启 |
| `drafting.agentId` | 继承插件 `agentId` | 开启工具时必须显式选择非主 Agent，建议 `dws-draft` |
| `drafting.documentWorkspaceIds` | 空数组 | 只读文档检索的知识库允许范围；空数组不检索文档 |
| `directBatch.mergeGapSeconds` | 30 | 1–300 秒；同用户相邻消息合并窗口 |

卡片有效期仍默认 30 分钟，草稿有效期仍默认 24 小时。私聊批次最长 5 分钟、安静等待 2 秒、最长等待 10 秒；近三条展示，本批最多 200 条，达到容量上限开始新批次。50 条/12000 字符限制用于历史上下文，缓存 30 秒，缓存和查询均按 profile、账号、会话及时间窗口隔离。发送领取后批次冻结。

正文删除后，SQLite 页优先复用，主库文件不保证立即缩小；后台使用 `PASSIVE` checkpoint，不在按钮交互中执行 `VACUUM`。本机合成数据检查已确认释放可复用页但文件仍保留原尺寸。现阶段不默认自动压缩：如需归还磁盘，应另开停机维护窗口、停止写入、备份并校验完整性，留足临时空间后执行互斥整理；失败保留原库，重启后复核身份、设置与待处理状态。不能在线替换正在使用的数据库，也不能把行数下降当作磁盘回收证明。

## 无工具与只读 Agent 两条路径

未启用工具时继续使用原 `runtime.llm.complete` 和插件 `agentId` 归属判断，无需新增 Agent。启用后采用 `runtime.subagent.run/waitForRun/getSessionMessages/deleteSession` 的两版共同接口；不传旧版不支持的 `disableTools` 等字段，不按失败自动换 Agent、模型、提供商或发送后端。

专用 Agent 使用独立工作目录：`<service stateDir>/dws-send-approval/draft-workspace/dws-draft`。任务可以在自身会话和此目录产生宿主管理的临时状态，不能修改用户工作文件或业务数据。最终发送仍由固定发送器校验，Agent 本身不发送。

工具允许清单必须恰好为以下四项，不接受 `alsoAllow`、按模型提供商或发送者额外加工具：

```json
{
  "allow": ["dws_draft_history", "dws_draft_contact", "dws_draft_search", "dws_draft_read"],
  "codeMode": { "enabled": false }
}
```

- 历史工具只能读当前任务已经固定的上下文，不能换会话。
- 联系人工具仅本人或已核实发送者的姓名、部门、职位，不返回手机号和邮箱。
- 检索仅使用管理员配置的知识库。查询结果还需核实节点类型和知识库身份，才返回本任务的临时资源句柄；无法核实就不返回资源。
- 只有完整、成功且为空的搜索才补充标题匹配：最多前三个允许空间的根目录各 50 项，最多返回 5 项，不递归或翻页，明确标为部分结果；错误或不完整搜索不启用补充。
- 文档读取只接受本任务句柄，读取前再次核实范围。没有任意 URL、文件路径、CLI 参数、执行命令、浏览器、消息发送、文件编辑或委派能力。

任务表绑定 profile、账号、Agent、会话、runId、草稿版本、截止时间；实际 SDK 工具集合必须恰好为四个工具且来源为本插件。Hook 检查后发一次性执行票据，执行器对最终参数再次校验；宿主 Hook 异常继续执行、后续 Hook 改参、伪造同名工具或迟到调用均拒绝。每任务最多 12 次查询，文档单次正文最多 8000 字符，单工具结果最多 16000 字符。

未知生命周期 Hook、动态工具加载、未经审核的插件或记忆插件会阻止启用。已检查的运行组合为本插件、钉钉 Channel、`memory-core` 及宿主内置 `openai` 提供商；外部安装的同名提供商仍拒绝。可信宿主安装和运行配置是前提，插件不能把恶意宿主变成沙箱。其他插件需先审查其生命周期行为；不要为了启用起草而不经评估删除生产插件。

## 富文本模板发布与迁移

只有一个生效模板配置 `assistant.cardTemplateId`。`templates/dws-reply-assistant-card-v3.json` 是可导入源码，平台编译导出另存于 `templates/dws-reply-assistant-card-v3.platform-export.json`。独立测试模板已发布并完成两版桌面呈现及回调检查；部署到其他组织仍须先发布自己的模板并完成验证。`compat/manifest.json` 固定了 MarkdownBlock 组件的上游提交和校验值；原 MIT 声明保留。

1. 在钉钉平台新建独立模板，导入 v3 JSON；完成平台编译、预览和发布，并保存包含编译后 `widgetInfo` 的平台导出。
2. 在隔离实例核验段落与强调、字面链接/图片语法、长文本与表单，以及两版宿主的可见卡片和按钮。确认完整正文、中文/Emoji、深色和大字表现；网页示意不能替代。
3. 通过后同时更新唯一 `cardTemplateId` 和 `cards.presentationVersion:3`。缺省版本 2 继续使用共用页面模型的纯文本呈现，不向未发布的模板启用富文本。版本 3 是部署显式确认，不从模板 ID 猜测能力。
4. 首次切换持久化撤销旧卡业务权限，再按原后端补刷升级提示。旧卡仅保留可信本人恢复导航；保存的设置、草稿、发送结果和去重关系不重置。普通重启不重复迁移。
5. 同一旧卡的恢复先持久化目标卡预留。结果未知时不换 ID 重发；旧入口过期使用 `/dws`。不能通过回退模板 ID 重新激活旧按钮；当前代码禁止展示版本 3 直接降回 2，部署回退需要单独验证并保留最新发送记录。

卡片表记录自身模板元数据，旧卡只有最小停用提示，无两套业务页面或两个生效模板 ID。第一版迁移前的旧记录可能缺模板元数据；通用更新接口按 cardId 更新，旧桥接的停用提示、恢复新卡、保留业务数据和旧发送拦截已在 2026.7.1-2 实测。管理员必须先完成平台预检再启用切换。

## 已知接口缺口与验收记录

- DWS 1.0.58 的实际历史接口缺少可靠源类型。2026-09-28 用户确认改为提取可用文字：过滤明确媒体/卡片类型、资源字段、图片语法及媒体占位，不读取附件；缺少类型时允许文字投影，不宣称能识别被转成普通文字的卡片。仍按会话、双方身份、时间、条数和字数约束，未知但明确声明的非支持类型保守排除。结果记录文字条数、过滤数、文字投影及附件未读取标记。此调整已通过两版真实私聊和群聊历史验证。
- 两版真实 Agent 已在隔离实例完成授权测试知识库的检索、读取和草稿生成，各实际调用两个只读工具并删除任务会话。新建文档在搜索中返回完整空结果，但目录列举和正文读取可用；受限标题补充取得文档后，仍经 `doc +inspect` 核实范围。测试知识库及虚构文档已移入可恢复回收站，原有知识库保留。输入为合成来信，不替代真实入站验证。
- 两版已在隔离实例完成真实模型、本人只读资料查询、草稿返回及会话删除；含写入、删除、执行命令和委派要求的恶意来信复验中，实际调用仍仅为只读查询，隔离哨兵文件不变。输入为合成消息，不替代真实来信与卡片批准；旧版认证方式见上文。
- 新版 N01—N09（N04 重测、N05R）和旧版 O01—O07（O02R）真实来信验证已完成；两版均覆盖主题命中与回退、固定确认、自动授权与冷却、私聊连续消息、私聊及群聊历史、只读 Agent 和到期授权。新版 N09 的恶意操作诱导来自真实他人来信；旧版 O07 实际只询问确认收到，因此旧版恶意操作约束的真实模型证据仍为前述合成输入探针。
- 两版均补验批量完整正文确认、私聊及群引用发送后的换行和字面符号。迁移时故意阻断停用刷卡，再真实点击仍可见的旧发送按钮，均只打开新卡，提示本次未发送，发送器调用为零，业务状态不变。这些用例使用独立夹具及真实卡片回调，不混称新来信。
- 共用 44 页渲染路径已修复换行；两版桌面代表页重新查看，用户在 iPhone 确认说明页、多行正文及最新回复详情的深色和大字体正常。不代表每页每种手机状态逐一验过；完整覆盖与限制见 [开发记录](../plans/2026-09-28-development-record.md)。

连续来信合并后的起草输入最多 8000 字符；超出时明确提示手动回复，不截断末尾后生成貌似完整的草稿。历史上下文的 12000 字符限额独立计算，截断会显示上下文不完整。
