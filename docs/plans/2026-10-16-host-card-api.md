# 宿主原生卡片接口适配记录

本次适配上游 PR #630 的公开接口修订，保留员工配置、状态目录、卡片逻辑 ID 和旧版桥接。

## 实现

- 现代宿主在同步插件注册阶段登记一次卡片回调，业务服务启动、身份刷新和重启复用句柄。
- 现代客户端依赖宿主的运行时能力和交互注册；旧宿主不加载新 SDK 子入口。
- 回调只接收业务字段，适配层恢复助手内部逻辑 ID，并查找当前活跃、身份已就绪的运行时。
- `isReady()` 为临时状态，不触发后端切换。请求失败不跨后端重试；既有持久化 backend 选择仍受尊重。
- 公司授权指引与正常助手共享预注册句柄，仍可在业务身份未就绪时投递无动作指引卡。
- Channel 现在遵循宿主失败后释放回调去重的语义；助手继续依赖业务状态、操作版本和发送状态防止重复副作用。

## 配套升级

此分支的 `compat/manifest.json` 标记 `apiRevision: 2`。新版 Channel 及助手须成套更新：使用清单中的固定基线与补丁，或已提供相同接口的上游版本。不能将新版客户端与旧版自建注册表接口混用。旧版 OpenClaw 2026.7.1-2 沿用原兼容分支。卡片模板和持久化业务数据无需迁移。

来源提交、最小补丁及客户端校验值以 `compat/manifest.json` 为准；生成后的最小补丁已在干净 main 副本应用并逐文件比对，结果与测试过的 Channel 实现一致。

- 助手：428 项单元测试通过；OpenClaw 2026.8.1 完整隔离宿主矩阵通过，包含真实插件入口、模型、身份与起草 SDK 验证。
- OpenClaw 2026.7.1-2：完整隔离矩阵通过；最终补充授权指引路径后，428 项测试和实际插件入口再次通过。旧版未加载现代客户端。
- 独立审查确认候选注册与激活、共享 runtimeContexts、账号 lease 清理和停止/刷新期间拒绝业务回调；发现的授权指引遗漏已修复并补测试。
- 2026-10-16 新版真机：公开接口发卡实际渲染；本人填写并提交验证文本，宿主接收回调并更新同一卡片。真实 `/dws` 入口、回复方式页面、默认规则编辑及按原值保存均通过，显示“回复规则已保存”。
- 本次没有重新做旧版钉钉客户端人工交互验收；旧版兼容结论来自上述实际 SDK 隔离矩阵。未重新验收 AI 起草或对外发送业务链路，它们不在本次接口变更范围。

本机预热后 10,000 次无网络/业务 IO 的协议回调，P95 约 0.016 ms，堆内存增量约 0.75 MiB（含宿主去重与采样数组）。这不是生产容器时延或资源占用承诺，未据此推算 Kubernetes 集群容量。

## 环境恢复与限制

真机期间临时切换全局 OpenClaw 的插件路径，结束后原配置逐字节恢复。测试只按原值保存回复规则，没有改变监听或自动回复策略。原 Channel 工作目录的 68 个已有变更文件哈希一致，两个原兼容分支及独立项目 main 未修改。

宿主 `openclaw message send` 的 scoped registry 频道选择曾报告 Unknown channel，已在不导入本改动的纯内存程序中复现；本次没有改宿主或启用默认关闭的主动发送 RPC。真实卡片验收通过临时消费者和真实 Stream 回调完成。
