## 2. 本轮修正

1. 区分已确认产品结论与默认参数、实现建议、技术验证项；原待定参数已按用户最后答复更新为已确认，技术可行性验证仍须实际完成。
2. 补齐主题/设置升级约束：preferences/settings 的 version:1、原模式/规则/授权保留、缺省字段补齐、旧数据不重放、无效配置不静默清空，以及对应脱敏升级夹具。
3. 明确固定正文/自动答复的对照表只描述 0.8.0 现状；未来统一固定回复入口的结论不变。
4. 按用户最新决定暂缓服务号过滤，并撤销“暂停自动发送、转人工核实”的配套建议。DWS 有类型透传字段不代表已经验证可靠识别，相关开发、提交和验收均移出本次范围。
5. 明确有工具起草需要宿主 Agent 配置；无工具默认不受新增 Agent 配置要求影响。
6. 区分页面 topic-review（规则向导核对页）与旧草稿状态 topic-review（历史待判断）。保留前者不代表新消息又出现主题第三态。
7. 记录到期检查默认 10 秒且可配置的单独确认，明确有效期仍为 30 分钟，配套独立轻量调度、限速退避、公平重试及交互性能验证。
8. 根据用户后续“其他待确认的都按你的建议来”，将数据保留、重清理默认值和连续私聊参数全部标为已确认；同步需求、配置建议、批次行为与边界验收。

## 3. 确认状态与技术验证

此前提出的待定项已全部收束：到期检查先获单独确认，数据保留/重清理默认值、连续私聊及起草等待参数随后获统一确认，具体值见总需求 1.1。目前没有遗留的产品参数澄清项。服务号过滤暂缓，原“类型无法核实的处理策略”已撤销。本表保留开发前的确认基线；2026-09-28 已启动开发，当前实现及真机验收进度见执行记录。

需要开发方验证而非要求用户猜测的事项：

- 两版宿主所选 Agent 的所有可达工具执行路径均受只读约束，宿主生命周期行为不会修改用户业务数据。
- 新模板组件实际呈现、旧卡恢复按钮可见性及回调、新卡创建、平台错误补刷和双版升级流程。
- 并发、卡片恢复/清理、批次与历史的边界；按已确认默认值验证，技术预算在既定功能范围内通过测试校准，不擅自更改产品默认值。

已确认的设计不是对上述技术验证结果的预先保证。正式启动开发后继续定位直到真机通过，再按独立提交顺序交付；不能以“待用户自行测试”结束。
