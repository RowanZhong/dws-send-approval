# 0.9.2 公司统一授权的事件监听票据模式修订

日期：2026-10-23。基线：0.9.1 / `aa5cda9`。用户收到公司通知：统一入口授权后，所有 DWS 事件监听命令都需要 `--stream-ticket-mode custom`，并要求更新插件。

## 实现范围

- 实际监听服务通过 `subscriptionPlan` 生成的全部 `event consume` 参数均显式指定 `custom`，覆盖四类消息事件和单进程合并订阅。
- 保留的 `listenerArgs` 辅助函数同步改为等价的 `event consume`：sender 使用 `--open-dingtalk-id`，group 使用 `--group`，单事件与合并事件都指定 `custom`。本地 DWS 1.0.58 的 `+listen-im --help` 未提供此参数，因此不在该入口直接追加。
- 不新增配置项、不改变已有身份迁移策略；监听目标、profile、过滤、去重、回复、存储和卡片契约不变。按用户确认，版本升级为 0.9.2，包清单与锁文件同步。
- 新增实际监听服务到模拟 spawn 边界的参数回归，覆盖全部私聊、指定人员、全部群 @、指定群 @、额外发送者、合并宽范围和合并指定人员。检查事件类型、目标、custom 模式、ready 和停止流程；辅助函数也覆盖全部单事件及合并事件。
- 两份主文档按当前代码系统核对；用户手册修正就绪含义、页面入口、固定回复三步/五步流程、迁移前后提示和无记录排查，技术指南区分当前操作与历史验收。README、员工手册及技术部署指南同步说明修订和部署方式；HTML 从 Markdown 重新生成。文档首页标识采用“双版兼容检查通过”，避免暗示本次 custom 模式已完成真实事件投递验收。

## 部署

更新助手代码并正常滚动重启 Pod，使监听进程和 DWS bus 一并重启。保留持久卷、DWS 登录态、卡片模板 ID 和展示版本。检查新进程参数和实际新消息处理结果；不以单独的 ready 状态作为收到事件的证明。
